## 1. 구현 목표

### 1.1 주제와 문제 정의

**제주 버스 이용 집계 데이터를 자연어로 탐색·분석해, 노선·시간대·요일·정류소·승하차 유형·이용자 유형별 이용량이 높은 구간을 근거와 함께 찾도록 돕는 데이터 분석 에이전트**를 제안한다.

버스 운영이나 교통계획을 검토하는 사람은 데이터에서 이용량의 차이를 확인해야 하지만, 표와 컬럼을 직접 살피고 원하는 기준으로 집계하는 데 분석 지식과 시간이 든다. 이 도구는 비전문가가 질문으로 집계 기준을 정하고, 계산된 표·차트·출처·한계를 한 화면에서 확인하도록 돕는다.

### 1.2 대상 사용자와 페르소나

- **주 사용자:** 제주도민·행정 실무자·교통 데이터 분석 입문자
- **상황:** 특정 노선이나 시간대의 이용량을 살펴보고 운영 검토가 필요한 구간을 찾고 싶지만, 원시 표를 직접 분석하기 어렵다.
- **필요:** 질문에 맞는 데이터 선택, 재현 가능한 단순 집계, 집계 근거와 데이터 한계의 쉬운 설명

### 1.3 사용 시나리오

사용자가 “노선별 이용량을 보여줘”라고 묻는다. 에이전트는 버스 노선별 이용 현황 데이터셋을 선택하고 노선별 합계를 표와 차트로 제공한다. 현 MVP의 기본 시연 데이터는 합성 자료이므로 결과 화면에 합성 데이터임을 표시한다. 실제 자료가 등록되고 컬럼·요청 조건이 검증된 뒤에는 시간대·요일·승하차·이용자 유형별 집계를 지원한다. 결과는 “검토할 이용량 상위 후보”로만 설명하며 혼잡도·좌석 점유·배차 결정을 추론하지 않는다.

### 1.4 차별점

- 자연어 질문을 정해진 데이터 차원과 집계로 연결해 비전문가의 탐색 진입 장벽을 낮춘다.
- 계산된 이용자 집계와 그 출처·합성 여부·한계를 결과에 함께 표시한다.
- 차량 정원이나 잔여 좌석 정보가 없는 승객 태그 집계만으로 혼잡률·혼잡 예측·최적 배차를 주장하지 않는다.

## 2. 서비스 제안

### 2.1 데이터 활용 개요

주 데이터는 명세서에 반출 가능으로 기재된 **3-02 버스 노선별 이용 현황**과 **3-04 버스 정류소별 이용 현황**이다. 요일·시간·노선·정류소·승하차 유형·이용자 구분에 따른 이용자 수를 집계한다. **5-02 일일 날씨 정보는 MVP 분석 범위에서 제외**하며, 별도 후속 연동 후보로만 둔다.

### 2.2 핵심 기능

| 기능 | 설명 |
|---|---|
| 질문 이해 | 질문에서 노선/정류소 데이터와 노선명·시간대·요일·승하차·이용자 유형 등 집계 기준을 결정한다. 모호하거나 지원하지 않는 요청은 현재 지원 범위를 안내한다. |
| 데이터 탐색 | 데이터 카탈로그에서 반출 허용 및 등록된 데이터셋을 찾는다. 현 MVP는 로컬 카탈로그와 합성 시연 자료를 사용한다. |
| 이용량 집계 | 선택된 차원의 `user_count`를 합산하고 표와 차트로 제시한다. |
| 근거·한계 표시 | 데이터셋명, 출처와 실데이터/합성 여부를 표시하고, 이용자 수 집계가 좌석·정원·혼잡의 측정값이 아님을 명시한다. |
| 검토 후보 제시 | 이용량이 높은 그룹을 후보로 정렬해 제시한다. 운영 결정이나 최적 배차를 자동 권고하지 않는다. |

### 2.3 편의성과 활용성

Streamlit 단일 화면에서 자연어 질문을 입력하면 요약, 그룹별 이용자 수, 차트, 출처·데이터 유형·한계를 확인한다. 질문 예시는 “요일별 노선 이용량 비교”, “정류소별 하차 이용자 수”, “시간대별 어린이 이용량” 등이다. 실제 데이터가 연결되면 질문의 조건이 해당 데이터 컬럼으로 확인될 때만 그 조건을 반영한다. 데이터에 없는 조건이나 지표는 계산하지 않고 한계를 안내한다.

### 2.4 분석 및 해석 범위

분석은 반출 승인된 집계 데이터의 `user_count` 합계와 차원별 비교로 제한한다. 수치 비교는 관측된 집계의 기술이며 원인·미래 수요·좌석 점유율을 의미하지 않는다. 상세한 기간·필터 조건의 질의 지원은 해당 원시 자료의 실제 컬럼·기간 확인 후 확정한다.

## 3. 에이전트 구성

### 3.1 역할과 도구

| 단계 | 역할 | 수단 | 제한 |
|---|---|---|---|
| 질문 해석 | 분석 대상과 요청 차원 식별 | 규칙 기반 키워드 매칭(현 MVP), 향후 로컬 LLM 보조 가능 | 실제 데이터에 존재하는 컬럼만 사용 |
| 카탈로그 탐색 | 노선/정류소 데이터 후보 선택 | 로컬 메타데이터 카탈로그 | 허용 데이터만 등록 |
| 데이터 로드·검사 | 필요한 컬럼과 데이터 유무 확인 | pandas CSV 로더 | 읽기 전용, 원본 파일 변경 없음 |

| 결과 표시 | 표·차트·출처·한계 출력 | Streamlit 또는 CLI | 합성 여부를 눈에 띄게 표시 |

### 3.2 워크플로

`질문 → 데이터셋 선택 → 데이터/요청 차원 확인 → 이용량 집계 → 표·차트·요약 → 출처와 한계 표시`

현재 구현은 CSV 샘플을 선택해 합산·요약하는 작은 MVP다. 향후 실데이터 연결 전에는 컬럼명·기간·분류 코드·결측값을 확인하고, 요청을 뒷받침할 수 없는 경우 명시적으로 범위를 좁히거나 결과를 제공하지 않는다.

### 3.3 모델 및 외부 서비스

- 기본은 외부 호출이 없는 mock 요약이며, 수치는 pandas가 계산한다.
- Ollama는 사용자가 별도 설치·설정한 경우 로컬 요약 용도로 선택할 수 있다.
- OpenAI는 선택적 외부 API이며 기본 비활성이다. 사용 전 전송 대상과 이용 조건을 확인한다. 데이터 원본 또는 키를 저장소에 포함하지 않는다.
- 현 MVP는 LLM에게 분석 코드를 생성·실행시키지 않으며 임의 코드 실행 샌드박스도 사용하지 않는다.

위 항목·필드 표기는 전달받은 데이터명세서_kr.xlsx(2026-11-04 v13) 확인 내용에 근거한다. 명세서 파일 자체는 참가자 전용 자료이므로 저장소와 제출 산출물에 넣지 않는다. 이 작업 시점에 원시 자료를 받지 않았으므로 실제 파일명·상세 출처·이용 조건·관측 기간·결측·분류 코드의 실제 값은 미확인이다. 실데이터를 반출·저장하기 전 공식 이용조건을 확인하고, 실제 파일을 받으면 데이터 카탈로그와 이 문서를 갱신한다.

### 4.2 전처리·분석 절차

1. 반출 허용 확인 및 공식 이용조건 확인 후 허용된 파일만 `data/private/`에 둔다(커밋 금지).
2. 실제 컬럼과 데이터 형식을 명세와 대조하고 날짜·시간·요일·이용자 분류·승하차 코드를 검증한다.
3. 누락·중복·범위 밖 값 및 데이터 기간을 점검하고, 분석에 포함된 조건과 제외 건수를 기록한다.
4. 질문에 맞는 기준으로 `user_count`를 합산한다. 정류소 현황과 노선 현황은 각각의 원래 집계 단위를 유지하고, 제공되지 않은 키로 두 데이터를 결합하지 않는다.
5. 수치·출처·자료 종류·기간·한계를 결과와 함께 표시한다. 데이터 연결 전 시연 결과에는 합성 데이터임을 고정 표시한다.

### 4.3 이용조건·보안·제한

참가자 전용 목록·키·원시 데이터는 저장소에 포함하지 않는다. `user_count`는 태그 기반 이용자 집계이지 차량 정원이나 잔여 좌석 정보가 아니다. 따라서 혼잡률, 차량 혼잡 예측, 최적 배차·노선 변경을 제안하지 않는다. 날씨는 MVP 분석에 포함하지 않으며, 후속 연동 시 별도 데이터 이용 조건·시간/공간 기준·해석 한계를 검토한다.

## 5. 개발·배포 계획

### 5.1 개발 범위

- **현재 MVP:** Streamlit/CLI, 로컬 카탈로그, 합성 버스 노선·정류소 CSV, 이용량 그룹 집계, mock 요약, 출처·합성 여부·한계 표시.
- **후속 개발:** 허용된 실데이터 등록, 실제 컬럼/기간 검증, 데이터 적합성 진단, 더 세분화된 질문 조건 처리, 재현 가능한 분석 결과 내보내기.
- **제외:** 혼잡률·혼잡 예측·좌석 점유 계산, 최적 배차·노선 자동 결정, 날씨 결합 분석, LLM 생성 코드의 임의 실행.

### 5.2 기술 환경과 센터 PC

Python, Streamlit, pandas, python-dotenv를 사용한다. 목표 환경은 제주빅데이터센터 PC **Intel Core i7-8700 / GTX 1060 / RAM 32GB**다. 기본 mock 구성은 GPU나 외부 네트워크 호출 없이 실행한다. 로컬 LLM은 센터의 설치·정책·성능 확인 후 선택 적용하며, 본 제안은 해당 PC에서의 속도나 7–8B 모델 구동 가능성을 검증된 사실로 전제하지 않는다.

### 5.3 화면·오류 처리

질문 입력 후 결과 요약, 이용량 차트·표, 데이터 출처 및 자료 유형, 해석 한계를 보여준다. 카탈로그에 없는 요청, 필요한 컬럼 누락, 비어 있는 파일은 성공한 것처럼 대체하지 않고 사용자에게 오류·지원 범위를 알린다. 합성 샘플의 차트와 요약에는 시연용/실제 통계 아님을 표시한다.

## 7. 검증·일정·미확인 사항

### 7.1 평가 계획

- 노선·시간·요일·정류소·승하차·이용자 유형별 질문 예시를 만들고 각 요청이 맞는 데이터셋·그룹 컬럼으로 연결되는지 확인한다.
- 테스트용 CSV의 그룹별 `user_count` 합계를 pandas 결과 및 수기 계산과 대조한다.
