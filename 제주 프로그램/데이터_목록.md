# 데이터 준비 안내 — 처음 받은 개발자를 위한 필수 문서

기준: 2026-11-19 현재 `backend/app/hub.py`, `compute.py`, `collection.py`의 구현.
제공처의 최신 승인 조건을 새로 조사한 문서가 아니라, 이 프로그램이 실제로 요청하는 자료의 목록입니다.
ZIP에는 기존 DB가 없습니다. 더미 매출 CSV만 넣어서는 지역 비교 결산이 완성되지 않습니다.

## 1. 무엇을 준비해야 하나요?

| 구분 | 가져올 데이터 | 역할 | 준비 방식 |
|---|---|---|---|
| 필수 공개 자료 ① | 제주 전체 버스 일일 승객수 | 비교 날짜 판단, 제주 전체 참고 지표 | 제주데이터허브 API |
| 필수 공개 자료 ② | 일일 정류소별 버스 이용자 | 선택한 1~3개 정류소 승차량 | 제주데이터허브 API |
| 필수 공개 자료 ③ | 읍면동별 와이파이 사용량 | 선택한 동네의 방문 관련 이용 지표 | 제주데이터허브 API |
| 참고 자료 ④ | 기상청 ASOS 일자료 | 강수량·최대 풍속·비 온 날 비교 | 공공데이터포털 API |
| 참고 자료 ⑤ | 한국천문연구원 특일 정보 | 공휴일 이름과 날짜 | 코드 내 확인 목록 또는 공공데이터포털 API |
| 필수 사용자 자료 | 우리 가게 일별 매출·휴무 | 가게 매출 변화 계산 | 직접 입력 또는 동봉한 합성 CSV |

필수 공개 자료 3종이 선택 범위에 없으면 현재 버전은 결산 시작을 막습니다.
날씨·공휴일이 없다고 임의로 값을 만들지 않습니다. 참고 정보가 부족할 수 있습니다.
자료 준비 확인 통과와 통계 비교 가능은 별개입니다. 낮은 이용량·비교일 부족 등으로 판정 보류가 생길 수 있습니다.
버스 승차·와이파이 이용은 다른 가게의 매출이나 고유 방문객 수가 아닙니다.

## 2. 키는 어디에 넣나요?

1. 제주데이터허브 https://www.jejudatahub.net 에서 프로젝트와 사용 권한을 확인합니다.
   아래 3개 자료를 본인 프로젝트에서 사용할 수 있어야 합니다.
2. 공공데이터포털 https://www.data.go.kr 에서 기상청 ASOS 일자료와 한국천문연구원 특일 정보의 활용 승인을 확인합니다.
3. README 설치 안내대로 `.env.example`을 `.env`로 복사하고 본인의 값을 입력합니다.

```text
JEJU_HUB_KEY=본인의_제주데이터허브_프로젝트키
DATA_GO_KR_KEY=본인의_공공데이터포털_서비스키
LLM_URL=http://127.0.0.1:8766
APP_PORT=8770
```

위 값은 설명용 자리표시자입니다. 실제 키는 ZIP·GitHub·화면 캡처에 넣지 마세요.
현재 수집기는 날씨에도 DATA_GO_KR_KEY를 사용하며 KMA_APIHUB_KEY가 필수인 구현이 아닙니다.
LLM_URL은 데이터 제공처 키가 아니라 로컬 AI 서버 주소입니다.

## 3. 데이터별 정확한 요청 내용

### A. 제주데이터허브: 공통

요청 주소 형식: `https://open.jejudatahub.net/api/proxy/{dataKey}/{프로젝트키}`
아래 dataKey는 자료 식별자이며 비밀 프로젝트키가 아닙니다.
`limit=100`, `number=1`부터 페이지를 조회하고 `hasMore`가 끝날 때까지 처리합니다.
인증키를 넣은 전체 URL은 문서나 로그로 공유하지 마세요.

| 자료 | dataKey | 날짜·지역 요청 조건 | 응답에서 쓰는 항목 |
|---|---|---|---|
| 제주 전체 버스 일일 승객수 | `617bt7b7ttb1Datab7a7ttD6tbt7611t` | startDate, endDate: YYYYMMDD | baseDate, moveType, userCount |
| 일일 정류소별 버스 이용자 | `1b1ta1a1ba6t6a1ttt3bD6b1tb1t1D3t` | startDate, endDate, stationName | baseDate, stationId, stationName, moveType, userCount |
| 읍면동별 와이파이 사용량 | `7tttaDaD5ataaba75a57ttDtaDb6tb7t` | searchDate: YYYYMMDD, emd: 읍면동명 | baseDate, emd, category, userCount |

- 수집기는 날짜별로 요청합니다. 버스는 moveType이 승차인 행을 합산합니다.
- 정류소 API는 이름으로 요청한 뒤 stationId로 정확히 거릅니다. ID 앞의 0을 유지하세요.
- 와이파이는 읍면동·분류별로 합산합니다. 현재 비교에 사용하는 분류는 관광지, 해변, 올레코스, 테마거리, 공원, 숲길입니다.
- 일일 노선별 버스 이용자 자료는 현재 결산에 사용하지 않으므로 별도로 받을 필요가 없습니다.
- 제공처가 오류·미게시·빈 응답을 반환한 상황을 임의의 정상 이용량으로 대체하지 마세요.

### B. 기상청 ASOS 일자료

주소: `https://apis.data.go.kr/1360000/AsosDalyInfoService/getWthrDataList`
인자: serviceKey, numOfRows=60, pageNo=1, dataType=JSON, dataCd=ASOS, dateCd=DAY,
startDt/endDt=YYYYMMDD, stnIds=관측소 번호.
필드: tm(날짜), sumRn(일강수량 mm), maxWs(최대 풍속 m/s).
시연 대상 애월읍은 관측소 184(제주)를 사용합니다.
다른 읍면동은 backend/app/settings.json의 asos_station 매핑을 확인합니다.
관측소 자료는 가게 위치에서 직접 측정한 날씨가 아닙니다.

### C. 공휴일

주소: `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo`
인자: serviceKey, solYear=YYYY, solMonth=MM, _type=json, numOfRows=100.
필드: locdate(YYYYMMDD), dateName, isHoliday. isHoliday=Y인 행을 사용합니다.
현재 settings.json의 holiday_years에 포함된 2025·2026년은 코드에 포함된 확인 목록을 사용하고 API 조회를 건너뜁니다.
따라서 2026년 예시의 공휴일은 별도로 내려받지 않아도 초기 DB 생성 시 들어갑니다.
새 연도는 제공처 자료와 매핑을 확인해야 합니다.

## 4. 더미 10종을 결산하려면 이 범위를 준비하세요

- 읍면동: 애월읍
- 정류소: 애월환승정류장(애월리), ID `0003291` 한 곳
- 결산 주 월요일: `2026-11-02`
- 대상 주: `2026-11-02 ~ 2026-11-08`
- 기준 4주: `2026-10-05 ~ 2026-11-01`
- 공개 자료·매출 준비 범위: `2026-10-05 ~ 2026-11-08`, 총 35일
- 날씨 관측소: 184, 공휴일은 2026년 10·11월 범위
- 매출: `examples/결산가능_더미데이터_10종/`의 CSV 중 한 파일

위 공개 자료 범위는 더미 10종이 공통으로 사용합니다. CSV 10개마다 같은 공개 자료를 다시 받을 필요는 없습니다.
다른 정류소나 주간을 고르면 그 범위의 공개 자료도 준비해야 합니다.
정류소·읍면동 검색 목록은 backend/app/data/stops.json, emds.json에 이미 포함되어 있습니다.
목록이 있다고 일별 이용량까지 들어 있는 것은 아닙니다.

## 5. 실제 준비 순서와 명령

README에 따라 가상환경·의존성·프론트 빌드를 준비하고 .env를 설정한 뒤,
압축을 푼 weekly-report 폴더의 PowerShell에서 아래를 실행합니다.

빈 DB 생성 (기존 DB가 있으면 보존):

```powershell
.\.venv\Scripts\python.exe scripts/init_submission.py
```

더미 시연 범위의 준비 요청 등록 (아직 다운로드하지 않음):

```powershell
.\.venv\Scripts\python.exe scripts/prefetch.py --from 2026-10-05 --to 2026-11-08 --emd 애월읍 --stops 0003291
```

수집 실행:

```powershell
.\.venv\Scripts\python.exe scripts/collect_public.py --run --config collection-plan-demo.json
```

동봉한 collection-plan-demo.json은 최신 주간 요청을 새로 추가하지 않고 등록된 대기 요청을 처리합니다.
완전히 새 환경에서는 위에서 등록한 더미 시연 범위가 대상입니다.
이미 다른 요청이 들어 있다면 그것도 처리할 수 있으므로 '해당 한 건만 강제 처리'하는 옵션은 아닙니다.
일반 collection-plan.json은 지정 지역들의 최신 주간을 추가하는 운영용 설정입니다.
데이터수집_관리.cmd와 자동 예약은 기본 운영용 설정을 사용합니다. 더미 범위를 먼저 확보하려면 위 명령을 사용하세요.

준비 상태 확인 (외부 API 호출 없음):

```powershell
.\.venv\Scripts\python.exe scripts/check_demo_data.py
```

필수 자료 준비 여부와 기간 내 테이블별 저장 행 수를 확인합니다. 행 수는 해당 정류소만의 수나 비교 가능 날짜 수와 같지 않습니다.
실제 매출·휴무를 넣으면 포함 날짜가 달라질 수 있습니다. 최종 결산 가능 여부는 앱에서 확인하세요.
수집기는 종료됐다고 모든 자료가 준비된 것은 아닙니다. DB 상태와 아래 기록을 확인하세요.

```powershell
Get-Content runtime/collection-log.jsonl -Tail 5
```

## 6. 한도에 걸리거나 자료가 없을 때

- 자체 일일 호출 상한은 100회입니다. 제공 기관의 공식 한도를 의미하지 않습니다.
- 35일 × 3개 필수 자료만으로도 최소 약 105회가 필요할 수 있고, 페이지·재시도·날씨 요청이 더해집니다.
  따라서 빈 DB에서 하루 안에 준비가 끝난다고 약속할 수 없습니다.
- 상한·제공처 한도가 끝나면 중지하고, 다음 실행에서 저장한 자료를 재사용합니다.
- 같은 날 이미 시도한 미완료 요청은 반복 실행해도 다시 처리하지 않을 수 있습니다.
- 401/403 권한 오류, 제공처의 일일 할당량 초과, 자료 미게시를 구분해야 합니다.
- 키 승인과 조회 범위, 제공처 게시 상태를 확인하세요. 반복 클릭이나 임의로 호출 수를 초기화하는 방법을 쓰지 마세요.
- 요청이 등록돼도 항상 다음 날 완료되는 것은 아닙니다. 미준비 자료는 미준비로 안내합니다.
- 예전 prepare_demo.py로 사용자 DB를 복사하거나 DB를 공유할 필요가 없습니다.

## 7. 어디에 무엇이 저장되나요?

| 위치 / 테이블 | 저장 내용 |
|---|---|
| runtime/public-data.db / island_bus | date, boardings |
| runtime/public-data.db / stop_bus | date, station_id, boardings |
| runtime/public-data.db / wifi | date, emd, category, users |
| runtime/public-data.db / weather | date, stn, rain_mm, max_ws |
| runtime/public-data.db / holiday | date, name |
| runtime/public-data.db / fetch_log | 수집 여부·행 수·조회 시점. key는 조회 구분값이며 인증키가 아님 |
| runtime/public-data.db / collection_* | 호출 상한, 준비 대기, 성공 응답 페이지, 수집 잠금 |
| runtime/demo-seed.db | 새 브라우저 공간을 만드는 초기 스키마·공휴일 목록 |
| runtime/web-sessions/ | 각 브라우저의 가게·매출·결산 기록 |

정규화 테이블 외에 성공한 응답 페이지도 collection_pages에 캐시합니다.
그러므로 '외부 API 응답은 전혀 저장하지 않는다'는 설명은 정확하지 않습니다.
공개 지표와 사용자 매출은 구분하여 관리하고, 기존 DB 전체와 세션 DB는 제출본에 포함하지 않습니다.
키 없는 신규 환경에서 README만 따라 즉시 실제 공개 자료가 생기는 것은 아닙니다.
