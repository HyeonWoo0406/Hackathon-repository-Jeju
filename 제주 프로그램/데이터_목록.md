# 팀 공유용 데이터 목록

현재 운영: 공개 API는 정기 수집기만 호출한다. 아래 prefetch 명령은 자료를 즉시 다운로드하지 않고 준비 요청을 등록한다. 실제 실행은 `scripts/collect_public.py --run`이며 호출 상한과 제공처 한도를 적용한다. 최신 실행 방법은 [데모 실행 안내](데모_실행.md)를 따른다.

현재 구현 코드 기준: 2026-11-12. 실제 DB 파일이나 API 키 대신 이 문서, 테이블 생성 코드, 수집 코드, 가상 매출을 GitHub로 공유한다. 아래 API 정보는 현재 코드의 연결 정보를 정리한 것이며 제공 기관의 최신 이용 조건을 새로 확인한 목록은 아니다.

## 1. 외부 API에서 받는 자료

| 자료 | 제공처 / 코드의 자료 식별자 | DB 테이블·저장 항목 | 사용하는 곳 | 필요한 환경 변수 |
|---|---|---|---|---|
| 일일 정류소별 버스 이용자 | 제주데이터허브 / `1b1ta1a1ba6t6a1ttt3bD6b1tb1t1D3t` | `stop_bus`: date, station_id, boardings | 선택한 정류소 1~3곳의 승차량 비교 | JEJU_HUB_KEY |
| 읍면동별 와이파이 사용량 | 제주데이터허브 / `7tttaDaD5ataaba75a57ttDtaDb6tb7t` | `wifi`: date, emd, category, users | 동네 방문 관련 분류의 이용량 비교 | JEJU_HUB_KEY |
| 제주 전체 버스 일일 승객수 | 제주데이터허브 / `617bt7b7ttb1Datab7a7ttD6tbt7611t` | `island_bus`: date, boardings | 제주 전체 비교와 비교에서 뺄 날짜 확인 | JEJU_HUB_KEY |
| ASOS 일자료 | 기상청 / `AsosDalyInfoService/getWthrDataList` | `weather`: date, stn, rain_mm, max_ws | 비 온 날 및 날씨 확인 | DATA_GO_KR_KEY |
| 공휴일 | 한국천문연구원 / `SpcdeInfoService/getRestDeInfo` | `holiday`: date, name | 공휴일 표시 | DATA_GO_KR_KEY |

제주데이터허브 요청 주소는 `https://open.jejudatahub.net/api/proxy/{자료 식별자}/{프로젝트키}` 형식이다. 실제 키가 포함된 주소는 문서나 로그에 남기지 않는다.

기상청 요청 주소: `https://apis.data.go.kr/1360000/AsosDalyInfoService/getWthrDataList`

공휴일 요청 주소: `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo`

수집 구현은 [hub.py](backend/app/hub.py)에 있다. API 응답 전체를 그대로 보관하지 않고 날짜·지역·정류소 등의 단위로 필요한 값을 정리해 저장한다. 버스는 승차 자료를 사용하며, 와이파이는 분류별 값을 저장한 뒤 `settings.json`의 `visit_categories`에 속하는 값만 비교에 사용한다. 이용량은 고유 방문객 수나 실제 구매자 수를 뜻하지 않는다.

공휴일은 API와 별도로 `settings.json`의 2025~2026년 확인 목록도 사용한다. 기존 검증에서 공휴일 API를 받지 못한 이력이 있으므로, 각 팀원의 키로 사용 권한을 확인해야 한다.

## 2. 사용자 입력 및 내부 저장 자료

| 테이블 | 항목 | 자료가 생기는 방법 |
|---|---|---|
| store | id, name, emd, industry, stops | 가게 등록. stops는 선택한 정류소 목록을 JSON으로 저장 |
| sales | date, amount, closed | 직접 입력 또는 CSV/XLSX 업로드 후 저장 |
| report | week_start, body, created_at | 결산 계산. body는 결과 JSON |
| fetch_log | source, key, date, rows, fetched_at | API 수집 기록. key는 지역·정류소 등의 조회 구분값이며 인증키가 아님 |
| meta | key, value | 가상 자료 여부 등 앱 내부 상태 |

테이블 정의와 빈 DB 생성 코드는 [db.py](backend/app/db.py)의 `init()`에 있다. 현재 구조는 가게 한 곳용이며, 여러 가게를 동시에 운영하는 공용 서비스용 구조는 아니다.

날짜는 `YYYY-MM-DD`, 매출은 원 단위 정수다. 매출 0은 실제 0원이고, 빈 값은 입력 없음이다. 휴무는 별도 값으로 구분한다. 정류소 ID는 앞의 0이 유지되도록 문자열로 취급한다. 강수량은 mm, 최대 풍속은 m/s다. 수집하지 못한 자료를 임의로 0으로 채우면 안 된다.

## 3. 저장소에 포함할 작은 자료

| 파일 | 내용 |
|---|---|
| `backend/app/data/stops.json` | 정류소 선택·검색 목록 |
| `backend/app/data/emds.json` | 지역 선택 목록 |
| `backend/app/settings.json` | 비교 기준, 와이파이 분류, 기상 관측소 연결, 공휴일 확인 목록 |
| `backend/app/data/blocked.json` | 앱 문구 확인에 사용하는 목록 |
| `example-sales.csv` | 35일 가상 매출. 실제 가게 매출이 아님 |
| `.env.example` | 필요한 환경 변수 이름. 실제 키는 각자 `.env`에 설정 |

패키징 과정에서 생성되는 `dist/시험자료_5종`은 저장소에 포함하지 않는다. GitHub에는 아래 `examples/sales`의 명시적 가상 매출 파일만 둔다.

| 공유 파일 | 실험 내용 |
|---|---|
| `examples/sales/example-sales-01-area.csv` | 동네와 비슷한 흐름 |
| `examples/sales/example-sales-02-store-down.csv` | 가게 매출이 더 크게 줄어든 경우 |
| `examples/sales/example-sales-03-store-up.csv` | 가게 매출이 오른 경우 |
| `examples/sales/example-sales-04-saturday.csv` | 토요일 매출이 크게 줄어든 경우 |
| `examples/sales/example-sales-05-hold.csv` | 휴무로 비교일이 부족한 경우 |

가상 매출만으로 동네 비교까지 되는 것은 아니다. 해당 기간의 공개 자료도 수집해야 한다. 같은 기간의 다른 매출 파일을 저장하면 기존 매출이 바뀌므로 시험용 DB에서 사용한다.

## 4. 팀원이 공개 자료를 준비하는 방법

Python 환경과 의존성 설치 방법은 [README](README.md)를 따른다. `.env.example`의 이름에 맞춰 본인의 API 키를 설정한 뒤, `제주 프로그램` 폴더에서 실행한다.

```powershell
.venv/Scripts/python.exe scripts/prefetch.py --from 2026-10-05 --to 2026-11-08 --emd 애월읍 --stops 0003291,0001087,0001082
```

이 명령은 지정한 범위의 준비 요청만 등록하며 공개 API를 호출하지 않는다. 정기 수집기의 저장 위치는 `runtime/public-data.db`다. 개발 실행과 실행 파일의 DB 위치는 다르다. 실행 파일은 기본적으로 실행 파일 옆 `data/app.db`를 사용하므로 실제 매출이 들어 있는 DB를 다른 파일로 덮어쓰지 않는다.

예시 검토 조건:

- 지역: 애월읍
- 정류소 ID: `0003291`, `0001087`, `0001082`
- 자료 기간: 2026-10-05~2026-11-08, 기준 4주와 대상 1주
- 결산 대상 주 월요일: 2026-11-02
- 가상 매출: 위 5종 중 한 파일

이 기간은 재현용 예시이며 최신 자료라는 뜻은 아니다. 다른 주를 분석하려면 그 주와 앞선 4주의 매출·공개 자료를 준비해야 한다. 공개 API의 게시 상태나 사용 권한에 따라 수집이 불가능할 수 있다. 자료가 부족하면 결산을 보류하거나 부족한 항목을 표시한다.

## 5. GitHub 공유 범위

실제 `*.db`, `.env`, 모델 파일, 실행 파일, 빌드 결과물, 로그, 방문자별 세션은 프로젝트 루트 `.gitignore`의 제외 대상이다. 코드, 이 목록, 작은 기준 목록, 가상 매출, 수집 스크립트만 공유한다. 실제 가게 매출과 인증키는 포함하지 않는다.

프론트엔드는 DB 파일을 직접 열지 않고 백엔드 API에서 결과를 받는다. 이 문서는 데이터 목록이며 화면 연결에 필요한 API 요청·응답 명세와는 별개다.
