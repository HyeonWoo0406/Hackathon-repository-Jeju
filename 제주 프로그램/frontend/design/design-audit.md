# 프론트엔드 디자인 검수

검수일: 2026-11-16

## 범위와 검수 방법

- 대상: 가게 등록, 매출 입력, 결산 정상/자료 부족, 질문 패널, 로딩, 인쇄 스타일.
- 가게 등록: 앞선 실제 앱의 320~1440px 반응형 검증 결과를 사용.
- 매출·결산·질문·로딩: 기존 React 컴포넌트를 개발 전용 `audit-preview.html`에서 가상 데이터로 렌더링하여 PC 1440×1000, 모바일 390×844에서 확인.
- API 호출은 검수 페이지 내부의 가상 응답으로 대체. 실제 매출·가게·공개 자료·백엔드는 변경하지 않음.
- 인쇄: CSS 코드 검토만 수행. 실제 A4 출력 및 페이지 분할은 미검증.
- 태블릿의 매출·결산, 실기기 키보드, 스크린리더, 전체 색상 대비는 추가 검증 대상.
- 검수 도구의 상단 선택 영역은 실제 제품 UI가 아님. 아래 높이 측정에 이 영역과 검수용 헤더가 포함됨.
- 기존 크림색·초록색 및 기존 시안은 폐기 예정. 색상 취향의 점수화보다 읽기·입력·오해 방지 문제를 우선한다.

## 우선 해결: 데이터 해석과 핵심 작업

### A01. 모바일 그래프의 글자가 지나치게 작다

- 확인: 결산 정상 상태, 화면 너비 390px.
- SVG의 너비가 317px이며 고정 viewBox는 700px. 11 단위 보조 문구의 표시 크기는 약 4.98px이다. 그래프 아래 수치는 CSS상 9px이다.
- 영향: 확인할 요일과 비교 제외 표시를 읽기 어렵다. 사용자는 작은 그래프와 더 작은 숫자 목록을 왕복한다.
- 제안: PC는 비교 그래프, 모바일은 충분한 글자 크기의 요일별 행 또는 선택형 상세로 표현한다. 같은 데이터를 써도 기기별 구성을 달리한다.
- 완료 기준: 요일·단위·핵심 변화율이 축소되지 않고 읽힌다. 그래프에는 수치 기준과 범례, 텍스트 대체를 제공한다.

### A02. 모바일 결산표가 핵심 비교 수치를 가린다

- 확인: 390px에서 표의 표시 영역 317px, 내부 너비 497px.
- 영향: 항목 이름, 기준 수치, 변화율을 한 번에 보기 어렵다. 가로 스크롤 자체는 동작하지만 핵심 변화율이 첫 시야에 없다.
- 제안: 모바일은 항목명·변화율을 먼저 보여주고 대상/기준 수치는 상세로 연결한다. PC 표는 유지할 수 있다.
- 완료 기준: 모바일에서 가로 이동 없이 핵심 비교를 읽을 수 있고 정확한 원값도 접근 가능하다.

### A03. 최초 매출 입력이 너무 길다

- 확인: 최초 상태에서 35개 금액 입력란, 5주 모두 펼쳐짐. 390px에서 검수 페이지 전체 높이 4860px.
- 영향: 현재 작업 주와 저장/결산 행동 사이가 멀고, 어느 주를 얼마나 준비했는지 알기 어렵다.
- 제안: 파일 업로드와 직접 입력 경로를 분명하게 구분한다. 대상 주와 기준 4주를 구분하고 주별 입력/휴무/미입력 상태를 요약한다. 진행률은 입력 상태를 설명하며 백엔드 결산 가능 조건을 새로 정의하지 않는다.
- 완료 기준: 현재 주와 입력 상태를 쉽게 찾고, 저장 상태 및 결산 불가 이유를 인지할 수 있다.

### A04. 자료 없음과 0이 그래프에서 같은 모양이다

- 확인: 자료 부족 가상 응답에서 null인 동네 값 7개가 높이 0인 막대로 렌더링된다.
- 영향: 아래 텍스트는 비교 불가이지만 그래프만 보면 변화 없음으로 오해할 수 있다.
- 제안: 자료 없음·휴무·비교 제외·변화율 0을 각기 다르게 표시한다. null을 0으로 보이는 시각 표시에 넣지 않는다.
- 완료 기준: 범례와 날짜별 상세에서도 같은 의미로 구분한다.

### A05. 자료가 없는 값에도 단위가 붙는다

- 확인: 자료 부족 상태에서 표에 `자료 없음명`이 표시된다.
- 제안: 값이 null이면 단위 없이 `자료 없음` 또는 명확한 대시를 보여준다. 합성 지표 이름과 개별 지표 단위는 데이터 명세를 기준으로 확인한다.
- 완료 기준: null, 0, 양수, 음수에서 숫자와 단위 표현이 자연스럽고 일관된다.

### A06. 요약의 '동네 평균'이 측정 대상을 오해하게 한다

- 확인: 결산 요약은 '동네 평균', 그래프는 '동네 지표'로 표현된다.
- 영향: 실제로 동네 가게의 평균 매출을 비교하는 것으로 읽힐 수 있다.
- 제안: `동네 이용 지표`처럼 측정 대상을 드러내는 이름으로 통일한다. 산출 기준과 버스·와이파이의 한계를 상세 설명에 둔다.
- 완료 기준: 동네 매출·구매자·고유 방문객 수를 측정한 것처럼 보이지 않는다.

### A07. 초기 연결 실패에 복구 동작이 부족하다

- 확인 방법: App.tsx 코드 검토. 실제 API 장애를 일으키지는 않음.
- 상태 조회 실패는 무시하고 저장된 자료/기본 문장으로 보인다. 가게 조회 실패는 ready가 false인 상태에서 오류와 초기 로딩 문구가 함께 남는다. 날짜 null도 계속 '확인 중'으로 표시된다.
- 제안: 로딩·설정 미완료·자료 없음·연결 실패를 구분하고 다시 시도 행동을 제공한다.
- 완료 기준: 사용자는 현재 작업 가능 범위와 복구 방법을 알 수 있다. 추가 서버 정보가 필요하면 담당자에게 요구사항을 전달한다.

## 함께 정리할 공통 UX와 시각 체계

### B01. 삭제 행동이 지나치게 노출되고 중복된다

- App 상단과 Report 하단에 전체 자료 삭제 진입이 있다.
- 가게 설정의 자료 관리 영역으로 위치를 통일하고 삭제 범위를 구체적으로 표시한다.
- 파괴적 행동은 현재 작업의 주요 버튼과 분리한다.

### B02. 최초 설정 단계와 반복 사용하는 메뉴가 섞여 있다

- 단계 탭, 돌아가기, 정류소 변경이 함께 존재한다. 결산 결과는 메모리 상태에 있어 새로고침 후 같은 화면 복원 경험이 별도로 필요하다.
- 처음에는 설정을 안내하되 이후에는 매출/결산 작업을 중심으로 구성한다.
- 저장된 결산 목록 및 복원은 기존 API로 가능한 범위를 먼저 확인하고, 범위 밖은 연동 요구로 남긴다.

### B03. 정류소 선택의 목적과 중복 이름 구별이 부족하다

- 정류소가 매출 비교에 쓰이는 이유를 선택 영역 가까이에 설명한다.
- 선택 개수와 선택된 항목을 안정적으로 표시한다.
- 방향·주소 등 추가 식별 정보가 API에 없다면 임의로 만들어 표시하지 않는다. 제공 데이터가 필요한 항목으로 구분한다.

### B04. 질문 패널의 모바일 배치와 터치 크기를 다듬어야 한다

- 확인: 390px, 세로 스크롤바가 있는 환경에서 패널 왼쪽 좌표 -3px, 오른쪽 363px, 문서 표시 너비 375px.
- `100vw` 기반 패널 너비와 스크롤바가 공존하면서 왼쪽 일부가 벗어난다.
- 바로가기 버튼 높이는 32px. 주요 버튼과 터치 영역 기준을 통일한다.
- 작은 화면에서는 결과를 덮는 패널의 크기·위치·닫기·가상 키보드 대응을 함께 설계한다. 실기기 키보드 동작은 미확인.
- 로컬 가상 응답 표시와 패널 닫기는 확인. 실제 모델 응답 품질을 검증한 것은 아니다.

### B05. 로딩 안내가 길고 문장이 중복된다

- 모바일에서 스피너, 시간, 설명, 추가 설명, 경고, 취소 설명이 한 창에 모여 있다.
- 작업 상태 한 줄, 필요 시 추가 안내, 취소 행동으로 위계를 단순화한다.
- 실제 단계별 진행 정보가 없으면 가짜 진행률이나 단계를 만들어 표시하지 않는다.
- 가상 검수 모달 열기·취소는 확인. 실제 작업 취소 API는 이번 범위에서 검증하지 않았다.

### B06. 글자·간격·상태 스타일의 공통 기준이 필요하다

- 역할별 타이포그래피, 숫자 자릿수/단위, 여백 단계, 버튼 위계, 입력·오류·비활성 상태를 정의한다.
- 본문과 증거 문구에 각각 최소 가독성 기준을 적용한다. 원본 SVG 텍스트 크기뿐 아니라 최종 표시 크기도 확인한다.
- 새 팔레트는 레퍼런스 연구와 사용자 선택 후 결정한다. 현재 화면의 색을 소폭 수정하는 방식으로 확정하지 않는다.

### B07. 인쇄와 모바일 가독성은 별도로 검증해야 한다

- print.css는 A4 스타일을 갖추고 있으나 이번에는 출력하지 않았다.
- 화면을 단순 축소한 PDF가 되지 않도록 행 잘림, 출처, 판정, 날짜, 단위의 출력 가독성을 확인한다.

## 유지할 좋은 기반

- 3단계의 기본 작업 흐름.
- 입력 라벨과 주요 버튼의 기본 크기.
- 파일 업로드 후 미리보기/저장 단계.
- 0원·휴무·미입력 구별의 데이터 개념.
- 결산 근거, 사용 자료, 한계 설명.
- 질문 실패 시 재입력을 돕는 기존 처리와 로딩 취소 진입.

## 권장 설계 순서

1. 화면별 목적과 정보 순서: 최초 설정 / 반복 매출 입력 / 결산 열람.
2. PC·태블릿·모바일의 레이아웃과 내비게이션 규칙.
3. 결산의 명칭·비교 기준·누락 데이터 시각화.
4. 숫자·글자·간격·버튼·폼·상태의 공통 컴포넌트 기준.
5. 결정된 구조에 레퍼런스 기반 시각 스타일을 적용.
6. 정상·빈 상태·자료 부족·오류·로딩·긴 텍스트·인쇄 재검증.

우선순위 A는 핵심 작업과 결과 이해를 방해하는 항목이다. B는 공통 설계에서 함께 해결할 항목이며, 코드 리뷰의 장애 등급을 뜻하지 않는다.
